Building a real-time investment analysis engine

Building an investment platform that powers a biotech hedge fund as successful as Perceptive is a real challenge. It has to provide enough value, and be designed well enough, that investors use it as part of their research process rather than play with it as a fancy demo. This writes an investment memo on a drug company from public filings with no human step. Reference run: KYMR.

Why it is valuable

The two things that make it a product rather than a toy

It does things humans cannot

  • Scrapes the open internet for information analysts do not uncover through standard searching.
  • Evaluates newly available information every day. A new trial registration or filing gets parsed the moment it posts, rather than waiting for someone to read it.
  • Stress-tests theses against new data instantly, rather than requiring a human to reason through every scenario and update the memos by hand.

It is auditable and understandable

  • If Perceptive prides itself on being an impartial, value-focused investor, the technology should not introduce a bias of its own.
  • Every argument, dataset and estimate, retrieved or generated, traces back to its source material, so we know exactly what fed a decision.
  • If a regulator asks what went into the research process, there is a stack to show them.
  • We can change how the models behave to trial different research hypotheses, so we know how we reached a conclusion rather than just what it was.
  • Given those characteristics, I have architected the platform below.
  • This is three days of work and a demo of what is possible at a firm like Perceptive. The known gaps are covered further down.
Architecture

The pipeline

  • The model reads the evidence and writes the memo. Code does the arithmetic.
  • Evaluation is a separate pass, covered below.
01Ingestion. Filings, trials, labels, epidemiology, pricing, and literature from public APIs into a per-company corpus.
02Retrieve (RAG). A BM25 index over that corpus; several queries per question return a small labeled evidence set.
03Compute. The model pulls the cited parameters from that evidence, and code does the arithmetic (peak sales, NPV).
04Generate memo. Compose the cited memo from the analysis, or refuse if a required section has no grounded claim.
05Serve. A SQLite ledger records every memo, claim, and run; a read API and web app expose it.

Deployment

  • Deployed on Render as two services: a FastAPI read API and a Next.js web app.
  • Committed data snapshot (corpus, ledger, one memo per company), so the API and app run from a clone with no key. A key is only needed to write a new memo.
  • Built in-house: the BM25 retriever, the grounding and evaluation harness, and the ledger. The only things off the shelf are the model API and click. Everything in the retrieval and grounding path is code I can step through when a citation fails to resolve.
Retrieval · RAG

Pulling the evidence

  • BM25 over the ingested corpus: filings, trials, labels, epidemiology, pricing, literature.
  • The tokenizer keeps drug codes like KT-621 whole, so an asset query matches the passages that name it instead of splitting on the hyphen.
  • Several queries per question return a labeled evidence set, at most 14 passages, for the model to read.
  • The model may cite only IDs in that set, and every one of them resolves to a real passage. If a citation does not resolve, the claim does not ship.
  • Getting the right document back is mostly solved; picking the right line off it is not. A filing page will list several revenue figures or several trials, and the harder job is choosing the one the question is actually about. A later eval scoring hit@1 turned up cases where a mechanism term pulls up the wrong asset's trial, which is the sharpest version of that problem.
Evaluation

Grading the memo against its sources

  • Every claim is checked against the evidence it cites.
  • Numbers are graded by code. A model judges only where the call is about language, and never grades a number.
CheckWhat it asksBy
RetrievalDoes the right passage come back for a querycode
Epidemiology groundingIs the population cited to a real source and in a sane rangecode
FaithfulnessIs each claim actually supported by what it citesjudge
Judge probesDoes the judge get known-answer cases rightjudge
Known-badDoes a memo with shuffled evidence score far worsejudge
CalibrationDoes the judge agree with a humanjudge

The judge is tested before its scores count

  • Faithfulness uses a model to read a model, so on its own it can flatter what it grades.
  • Known-answer probes check whether the judge gets clear cases right.
  • Known-bad feeds it a memo with the evidence shuffled and requires the score to drop by a clear margin. If a scrambled memo scores as well as a real one, the judge measures nothing, so this runs first.
  • Calibration compares the judge's verdicts to a human's and reports the agreement as a number.
  • A case the checks caught: a population cited to a real source, but the prevalence of the wrong indication that read cleaner nearby. The epi check now adds a plausibility band and an over-aggregation detector, so a real-but-wrong number gets flagged.
  • Limit: there is no free public feed of analyst consensus. The claim the brief cares about most, where the view departs from the market, is argued from evidence rather than scored against a number.
Follow-ups

The valuation math is an area we would invest more into

  • The arithmetic is deterministic and repeats. The inputs and the modeling are what need work.
  • Retrieval and grounding are not what is holding this back; the modeling is.
  • Two peak-sales inputs are guesses. Penetration and net price are the two biggest multipliers and both are assumed, so the result swings on them.
  • The data to fix one is already ingested. CMS ASP and Medicaid NADAC are in the corpus but not read into net price, and there is no list-to-net bridge.
  • Success probability is coarse. Applied once in the NPV, which is right, but the modeling behind it is thin.
  • The NPV covers the lead asset only, so it understates the company. Treat it as a floor.
Long-term vision

Where this goes

  • From one memo to live coverage. Re-run on each new filing or readout so the memo updates itself and flags exactly what changed and why.
  • Coverage across a universe. Rank and compare many companies at once, surfacing where the model's view diverges most from the market's.
  • A valuation you can defend. Gross-to-net pricing, penetration drawn from real analog launches, and a sum-of-parts across the pipeline, so the number is something you could take into an IC meeting and argue.
  • Figures inside the argument. Insert and annotate the actual chart a claim rests on, wiring Stage 1 into the memo.
  • An evaluation you trust. A held-out labeled set and standing human calibration. Right now a good score mostly tells you the harness ran.
  • The analyst in the loop. Turn the comment and feedback trail into signal for where the memo is wrong, and feed it back.
