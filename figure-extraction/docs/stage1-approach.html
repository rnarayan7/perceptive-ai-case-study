Stage 1 · Figure extraction

Extracting values from biotech charts

We are given multiple biotech chart types, each with different data. We aim to design a system that automatically pulls the correct values out of these clinical trial charts without human intervention.

Why build it

What makes technology valuable in a biotech hedge fund

It does things an analyst cannot do by hand

  • Measure 186 bars off a waterfall and count how many clear a threshold.
  • Read every figure in a paper the day it posts, for about thirty cents.
  • Re-measure everything when the key changes. Most of what first looked like measurement error was the harness discarding correct values.

It is auditable

  • Each number comes from a pixel position and an axis. The conversion is arithmetic, so it repeats exactly.
  • Confidence comes from structural checks that need no answer key, so the system can decline instead of guessing.
  • Each value records where it came from: read from the paper, derived from it, or an unverified read. 13 of the 27 are unverified, and this says so.

This demo is a work-in-progress, and is simply meant to show the art of the possible rather than function as a fully fledged system.

Architecture

Utilizing VLMs and deterministic computer vision algorithms to classify images

What the vision model does

  • Classifies the figure.
  • Finds structure: panels, legend, series.
  • Reads printed text: axis labels, reference lines, patient counts.
  • Never returns a magnitude it had to measure.

What deterministic CV does

  • Locates rules, ticks and plot edges as pixel rows and columns.
  • Traces each series by colour, finding bar tips, marker centres and whisker ends.
  • Converts pixel positions through the axis, linear or log, into values.
  • Never decides what a position means. It cannot tell a tick from a letter stem.
01
Route. Figure type from the image, by a smaller model.model
02
Read structure. Panels, legend, series names, what each reference line marks, the printed N, the axis labels and the values they carry.model
03
Calibrate. Two labelled positions become an axis. Candidates enumerated by geometry, chosen by the model, accepted or rejected by invariants.both, in a loop
04
Measure. Bar tips, curve heights, marker centres and whisker ends, converted through that axis.geometry
05
Verify. Structural invariants accept the reading or decline the figure.geometry

Evaluation set

Building our eval suite

  • We started with the images provided in the case study prompt.
  • Annotated additional real figures harvested from the PMC Open Access corpus, rather than scoring only against the six supplied ones.
  • Every gold value carries provenance: taken from the source paper, derived from it, or an unverified read.
  • The scored set grew from 22 values to 26, so the evaluation got harder while the score rose.

Limits

Where it fails

In the system

  • Left edge truncation gives bad leftmost values and a 4% undercount, since sorting puts the deepest bars at the clipped edge.
  • Runs are not reproducible. Five runs of the same configuration ranged 0.731 to 0.923, because the reader intermittently emits nothing for the table, once dropping eight values.
  • Density ceiling. At 186 bars the count is short by seven. Below about 60, counts land exactly.

In the evaluation

  • Half the key is a manual read. 14 of 27 values come from public sources. The other 13, including all three forest values, were never published, so those scores measure agreement with a manual read rather than with a source.
  • Six figures is not evidence of generality. A held-out set would tell us more than another point of accuracy on these six.
  • Confidence drifts the wrong way. Calibration error rose to 0.305 as accuracy improved, because low-confidence answers keep turning out correct.
  • Single runs are noise. A forest improvement reported off one sample did not survive three repeats, so any figure quoted from one run needs repeating before it means anything.
Dead ends

Other approaches trialed

  • Circular anchor check. It verified the model's anchor against the model's own value, so it accepted a 2x error.
  • Containment check. It rejected a correct Kaplan-Meier axis that was fifteen pixels off.
  • Interval-endpoint tie counter. It fired on the known-good calibration as readily as the wrong one.
  • Chart-to-table model. All zeros on a nine-bar figure, and a 186-bar figure truncated to eighteen rows.
  • Open-vocabulary object detector. Zero boxes at every prompt and threshold; chart bars are not objects in a photo-trained vocabulary.
  • Connected-component segmentation for counting. Found 1 and 389 bars where a plain grid scan found 52 and 179.
Areas of investment

Long-term vision

  • Annotate more images. Six figures is not enough to tell a working system from a curve fit.
  • Train chart-specific CV calibration. Learn the axis and structure conventions per chart type instead of deriving them from scratch on every figure.
